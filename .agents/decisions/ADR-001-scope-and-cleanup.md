# ADR-001：原地 Mac-only 实施、旧版隔离与逐轮停测

- **状态**：Accepted
- **日期**：2026-11-22
- **决策人**：user
- **取代**：原始计划中“新建独立 V2 仓库、双平台对等、Windows 接力”的旧边界

## 背景

用户明确要求直接在当前项目仓库根目录上升级，并逐轮实测。原始计划默认
新建桌面仓库，先完成 macOS 再交接 Windows。继续沿用旧边界会引入迁移
成本、双平台回归面和不必要的 Windows 对齐工作。

## 决策

1. **唯一实现目录**：当前 Git 仓库根目录。本机克隆位置可以不同，但所有业务实现必须留在该仓库内。
2. **计划文档只读**：用户指定的外部计划目录仅用于阅读和核验，不修改其文件或时间戳；仓库文档不得依赖该目录的绝对本机路径。
3. **平台边界**：仅支持 Apple Silicon Mac，最低 macOS 13。不创建或修改 `.bat`、`.ps1`、NSIS、WebView2、WASAPI、`msvcrt` 或 Windows 测试。
4. **发布边界**：最终标签为 `v2.0-mac-ready`，只产出 arm64 `.dmg`。不创建 Windows 交接标签，不创建 `v2.0-stable`。
5. **逐轮停测**：每轮完成自动验证后创建 `checkpoint-rXX-ok` 并停止。用户明确回复通过后才开始下一轮；失败时按复现证据修复或回退到上一 checkpoint。
6. **旧版保护**：R01 提交作为 V1 基线。R07 前保留旧入口可运行；R07 后旧实现收口到 `legacy/v1`，并保留显式启动参数用于应急回退。
7. **外部资产**：只复用许可明确且已记录精确 commit 的代码；`hayamimi` 因许可元数据不明确，不复制任何源码。

## 后果

- 所有后续命令必须从目标目录执行，文档不得再使用独立 V2 仓库路径。
- 每轮变更需要更严格控制白名单，因为生产入口与实验代码共处一个工作树。
- 通过 checkpoint 和阶段标签承担隔离职责；任何跨轮变更都视为违反流程。
- Windows 相关讨论只保留为明确非目标，不进入实现、测试、安装包或交接。

## 验证

- 仓库根目录由 Git 工作树动态解析，不得在代码或可迁移文档中硬编码个人主目录路径。
- `tests/unit/test_repo_bootstrap_layout.py` 不得发现 `.bat` 或 `.ps1`。
- `tests/unit/test_contract_and_config.py` 校验 Mac-only 边界、契约状态与逐轮流程。
